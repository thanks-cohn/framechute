# SEKAI Stage 4 — Agentic Design

**Status: proposed architecture and workflow contract; not a claim of implemented API.**
**Project:** ÆRIS provides the cinematic flight and renderer foundation. SEKAI Stage 4 is the creator-first world-authoring, asset-placement and 2D/3D synchronization workflow built on the preceding map/geography/elevation work. The earlier proposal's TOPOS label is a legacy working name for this same workflow, **not a separate product or source of truth**.
**Companion:** [Shape-aware map workflow](./topos-stage-3-map-shapes-stage-4-asset-surfaces.md) (the preceding geographical foundation and Stage 4 initial asset placement). This document states the **agentic/API design requirements**; it does not change the existing stage gates or claim the tooling ships today.

## North star: effortless for people; exact, expansive and automatable for machines

A creator assembles their little authored Tiled maps in the larger world, draws a few optional lines/polygons/quadrilaterals/circles with meaning and defaults, imports the project, then **flies through it in ÆRIS and right-clicks to place assets**. Select a known GLB or upload one, choose a ground/floating position and orientation, optionally provide a support plane and preserve/generate terrain underneath, preview and confirm: **BAM**. SEKAI takes care of coordinate conversion, missing elevations, geometry, map links, footprint markers and consistent output files. The user need not write JS, hand-edit JSON or learn mathematical transformations.

**Every operation in that simple UI has an equivalent documented, versioned, machine-readable API operation.** AI agents should be able to inspect the precise world state, plan and preview changes, explain decisions, and carry out user-authorized modifications. Programmers should have enough breadth, depth, control and predictability to script sophisticated workflows, batch changes and build independent applications **without relying on an LLM, browser UI, screenshot inference, or proprietary agent service**. Agent-first means semantically precise and discoverable, **not agent-exclusive**.

## 1. Authoritative truth and file graph

- Canonical versioned `world.json` / **SEKAI World IR** is the single semantic identity and relationship graph for worlds, source maps, geography, surfaces, assets and placements. Preserve creator edits in ordinary editable Tiled files; the IR records their provenance, placements, scale and revision. Generated rendering JS/geometry and low-detail maps are **derived artifacts**, not independent conflicting authorities.
- Maintain one master/overview Tiled map plus references to as many small authored Tiled maps as needed. Define each local-map-to-world transform: source map ID/revision, tile width/height, x/z origin, rotation, scale, orientation, units and target world ID. **Do not assume a 50×50 detail map and one cell in a 500×500 overview map have the same world footprint.** The overview can show a compressed symbolic reference; the full local tile detail remains in its source file and is rendered on approach, without allocating a full 16,000² detailed grid.
- Store numeric heights and stacked surface relationships separately from semantic object notes. The companion **elevation JSON** keeps every numeric height numeric; a separate `objectAnnotations` metadata namespace or compatible sidecar says `OBJECT X HERE` and carries an object ID + surface ID for affected cells. It is `semanticOnly`, **non-rendering**, **non-colliding**, and cannot be parsed as a height value. Repeated annotations never create repeated GLBs or collision boxes.
- The named **object registry** owns the single canonical GLB instance, asset URI/library identity, version/hash, world/surface attachment, scale, pivot, rotation, bounds, occupied cells, and any separately declared collision/interaction behavior. The Tiled white-X overlay and elevation annotations are **references**, not extra objects.
- Preserve ground beneath floating structures: a world X/Z coordinate may have several independent named surfaces with different Y/normal/clearance/occupancy. A numeric elevation grid alone cannot encode that stack. Capture what lies underneath by explicit relationships, not by overwriting the base map.
- Give each region, surface, shape, map, asset and instance a stable ID; preserve IDs across reimport/rebuild. Every response identifies the world revision and coordinate space. Never infer intent, units or missing heights from visual similarity alone.

## 2. Canonical coordinate and spatial-query contract

Document a right-handed or explicitly declared coordinate convention, axes, units, origin, tileset pixel dimensions, and transform order. In this project, **Tiled local X/Y → canonical world X/Z** and numeric elevation → world Y; expose all intermediate transforms including small-map coordinates, master overview coordinates, global world coordinates, floating-origin render coordinates, parent/object-local space, camera space and normalized viewport/pixel space.

Offer typed, deterministic conversions between supported spaces; return structured errors when a conversion is ambiguous. Expose `worldToLocalMap`, `localMapToWorld`, `worldToOverview`, `overviewToWorldRegion`, `worldToViewport`, `viewportRayToSurface` (illustrative operation names), with precision/rounding policies and multiple-candidate results for stacked surfaces or a coarse overview tile. An overview tile is an area **not** automatically one exact world point.

Expose exact queryable geometry where known: `heightAt`, `surfaceNormalAt`, `sampleMaterial`, `getSurfaceStack`, `queryPlacementSurface`, `getOccupiedCells`, `getWorldBounds`, `getRelativeTransform`, `queryVisibleObjects` and `explainProjection`. Distinguish authored geometry, generated approximation, cached proxy and unknown. Expose renderer LOD/drawables separately from authoritative physical/world state; screen position is an observation, never the location of record.

For floating planes and islands, Stage 3's default `surfaceId` must support object placement **before** decorative undersides, mountains or complex terrain have been implemented. The same placement API works on ground, elevated platforms and floating island tops; it does not silently reinterpret water as walkable or assume a visible GLB automatically provides a collision surface.

## 3. Versioned, discoverable API — one contract for agent, coder and UI

Use a documented engine-neutral schema and transport adapter. The in-browser JavaScript API, a headless local CLI/SDK, an optional explicitly authorized agent/MCP bridge and the human UI call the **same validated core**. Do not force programmers through the UI or force agents to scrape DOM; do not assume a specific bridge is already implemented. Support ordinary functions, batch calls, typed records, paginated/sparse queries, event subscriptions and portable JSON inputs/outputs as appropriate. Distinguish synchronous cheap inspection from async file loading, generation, preview and commits.

| Domain | Example discoverable operations (proposed, not shipped) | Returned contract |
| --- | --- | --- |
| Discovery | `api.describe()`, `api.getCapabilities()`, `api.getSchema(version)` | Supported methods, schema versions, units, permissions, limits, declared unknowns and examples. |
| World/map | `world.inspect`, `world.listMaps`, `map.inspectRegion`, `map.compareRevisions`, `map.importTiled` | Exact source and world revisions, semantic tile IDs, changed/unchanged/missing regions and provenance. |
| Math/geometry | `spatial.transform`, `surface.query`, `surface.sampleHeight`, `surface.stackAt`, `spatial.projectToViewport` | Named coordinate spaces, units, validated transforms, normals, bounds, ambiguity and precision. |
| Geography | `shape.inspect`, `terrain.plan`, `terrain.preview`, `terrain.commit` | Shape type and meaning, exact/approximate boundary, generation seed, proposed affected chunks, surface and height changes. |
| Assets | `asset.list`, `asset.importGLB`, `asset.inspect`, `asset.getBounds` | Asset hash/ID, file location within authorized library, orientation, pivot, dimensions, license metadata, errors. |
| Placement | `placement.suggest`, `placement.preview`, `placement.commit`, `object.inspect`, `object.move`, `object.remove` | Single instance ID, support surface, transformed footprint, preview conflicts, object record, Tiled X overlay and elevation annotation delta. |
| Revisions/events | `transaction.plan`, `transaction.validate`, `transaction.commit`, `transaction.undo`, `events.subscribe`, `trace.explainChange` | Expected revision, provenance, bounded patch, atomic output manifest, machine-readable reason codes and event/cursor. |
| Renderer/debug | `renderer.inspect`, `renderer.getBudget`, `renderer.getViewportPosition`, `replay.capture`, `preview.rollback` | Physical versus displayed pose, camera and projection, geometry/LOD status, frame ID, limits and explicit unknowns. |

Define request/response JSON Schema (or single generated equivalent), semver and compatibility/migration rules, stable error codes, idempotency keys for retries, cancellation/progress for generation, deterministic seeded results and time/memory limits. Include code examples for both a beginner's `placeAssetAtClick(...)` shortcut and a programmer's transaction with explicit transforms and custom hooks. Provide **safe high-level convenience methods and comprehensive low-level primitives**, not a single opaque “make world” endpoint or a forced multi-form wizard.

## 4. The one-click happy path maps to transparent operations

1. **Combine small maps:** import authored map files, position them on the master map and store their source transforms and protected regions. The renderer uses the master to navigate and the local files for full fidelity, generating/caching only affected sparse chunks on edit/approach.
2. **Describe geometry:** creator uses Tiled's rectangles, polygons (including quadrilaterals), ellipses/circles and polylines in a TOPOS/SEKAI Shapes object layer, or a future optional equivalent browser drawing overlay. Shape-class metadata stores `landmass`, `lake`, `road`, `floating island` etc., plus `Default` or optional precise choices. Preserve legacy TOPOS-shaped metadata while displaying SEKAI as the current workflow name.
3. **Import and reconcile:** compare new Tiled revision with prior sources and World IR; only ask about genuine missing height/surface/semantics. Resolve safe defaults in one click; provide optional exact/approximate outlines, floating height, underside and underneath choices. Preview changed chunks and preserve unrelated authored tiles.
4. **Fly and place:** right-click an inspected world surface, pick/drop a GLB from library or authorized local upload; orient N/E/S/W, scale/pivot, choose On Ground / Elevated / Floating; optionally choose a cheap circular/plane support and `Preserve underlying ground` by default. Show safe footprint, contact and a clear preview before committing.
5. **Synchronize automatically:** ONE logical transaction updates master overview reference if needed, detailed small-map white-X footprint overlay, companion elevation JSON `OBJECT X HERE` pointer metadata, authoritative object registry/World IR and derived renderer data. Distinguish coarse overview marker from detailed tile footprints; preserve original elevation numbers and collision policy. If a source cannot be written in place, create an explicit compatible patch/export bundle and report exactly which files were written rather than claiming silent save.
6. **Iterate:** reposition/delete/replace the GLB and regenerate all derived references by stable ID; later swap white-X placeholder for a generated 2D/pixel-art tile representation without changing the object ID, transform, support surface or footprint truth.

The UI hides the complexity behind defaults. The API exposes the full inspected plan, calculated coordinates, all output deltas and revision proofs for programmers and agents.

## 5. Agent-native and programmer-grade requirements

- **Agent legibility:** every object and shape has an inspectable semantic description, exact coordinate/footprint provenance, relationships and decision trace. Return `missing` versus authored zero explicitly, conflict candidates rather than silent guesses, confidence and derivation only when computed from actual data, and machine-readable reasons for choices.
- **Deep mathematical access:** agents can query any world/region/surface/map/asset/instance through bounded paging and request precise world↔tile↔render↔viewport conversions, extents, normals, elevations, orientations, collision flags *where explicitly authored*, source revisions and current render state. Expose actual measured GPU occlusion only when captured; do not hallucinate raster truth.
- **Automation for programmers:** batch placement/terrain operations, custom validated presets and seeded procedural plugins, CLI/headless import/export, deterministic fixtures, query filters, subscriptions to revision/object change events, incremental patch/diff, transaction dry-run and rollback, stable schemas and clear performance envelopes. Expose extension points through versioned adapters, **not arbitrary eval of scripts inside a world asset**.
- **Authorization:** default read-only, explicit time- and world-scoped editor capabilities for mutation, explicit user approval for saving/exporting or touching local files. A map or GLB never inherits unrestricted filesystem, network, desktop, or unrelated FrameChute/SUBSTRATE tab access. All proposed operations should work without a mandatory AI or paid service.
- **Performance:** sparse map/chunk updates, bounded per-query and per-frame work, dynamic LOD/distant proxies, content-hash caching and no full 16,000×16,000 tile allocation. Readable defaults must work on lower-memory hardware; measure instead of promising FPS.
- **Documentation:** publish `agentic_design.md` as the navigation contract, a machine-readable schema/capability manifest, a sample project with 3 maps + one floating object, and a short agent start-here handoff mapping each API method to the true owner source file. Update the handoff and regression tests in the same change whenever a contract evolves.

## 6. Non-negotiable correctness tests and scope

Test a 50×50 local map edited inside a 500×500 master overview of a larger sparse world. A changed mountain/shoreline regenerates only affected cached outputs; unrelated authored cells and other maps survive. Polygon, rotated quadrilateral, ellipse and line metadata survive Tiled import and re-export, including local-to-world transforms. A new default ground or floating surface accepts placement. Right-click an uploaded GLB, adjust its transform, place it and verify the exact same stable ID in (a) canonical object record, (b) detailed map white-X overlay, (c) elevation JSON non-rendering annotation, and (d) master overview's correctly scaled reference. The 3D instance is created **once from the object registry**. Moving/deleting the asset updates all relevant references, without changing numeric heights or introducing accidental collision from `OBJECT X HERE`. Reimports are idempotent; failed multi-file outputs are reported/reverted. Test permission failures, ambiguous stacked surfaces, quality fallback and the 4 GB device separately from source-level validation.

**Stage boundary:** ÆRIS Stage 2 remains the flight/rendering foundation; complete the geographic import/surface prerequisites before SEKAI Stage 4's fast asset-placement and synchronization workflow. This file is design and acceptance intent, **not an implementation report**.
